# 1. The social preview image carries no project data

Date: 2026-10-04

## Status

Accepted

## Context

`public/og.png` is the image link previews show when the site is shared. An earlier version listed every project with its status and status colour. Those facts were copied by hand from the Project collection into a generation script that lived outside the repo, so adding or renaming a project silently left the preview wrong.

Generating the image from the Project collection at build time would fix the drift, but needs new dependencies (a layout engine such as satori plus a non-WOFF2 copy of the font) and a build-time rendering step, only to keep a preview card in sync.

## Decision

The preview image shows only the name, the subtitle and the domain. It holds no project data, and the Project collection stays the only place project facts live.

## Consequences

- Adding, removing or editing a project never requires touching the image.
- Status colours have a single consumer (the page CSS), so they stay defined there rather than in a shared Status module.
- The image repeats the name and subtitle from `src/pages/index.astro`; it must be regenerated by hand if either changes. That is rare enough not to justify build-time generation.
- Revisit if the image needs content that changes often.
